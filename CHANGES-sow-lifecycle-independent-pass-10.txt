SOW lifecycle — independent pass 10 (fresh, from the Oct 4 re-clone)
====================================================================
Section 9: app/(app)/sow, api/sow/*, lib/sow, lib/pdf (SOW portion), api/pdf/sow.
Six bugs, all fixed. No feature changes.

B1  A retainer's MONTHLY fee was presented as the "Contract value" on every SOW surface
    projects.contract_value is the monthly rate for retainers; the PDF header, portal page, signing email, the portal
    PDF, the frozen executed PDF built at signing, the registry "Value" column and the generator (prompt + fallback)
    all printed it as a one-off contract value. A client was asked to sign "USD 10,000" for USD 10,000 x 24 months.
    New lib/sow/retainer.ts is the single definition. PDF/portal/email now read "Monthly retainer fee USD X / mo"
    (plus "N months · USD T total" for a fixed term); the registry shows "/mo"; the generator tells the model the
    figure is monthly with the term, and the deterministic fallback (6 languages) says so; ensureContractValueStated
    appends "/ month". send-sow, both PDF routes, sign and the portal GET now select type + retainer_duration_months.
    Files: lib/sow/retainer.ts (new), lib/pdf/renderer.tsx, app/api/pdf/sow/[id], app/api/portal/sow/[token]
    (route, pdf, sign), app/portal/sow/[token]/page.tsx, lib/email/templates.ts, lib/documents/send-sow.ts,
    app/(app)/sow/page.tsx, lib/ai/sow-content.ts, app/api/sow/generate/route.ts.
    NOTE: executed PDFs already stored for signed retainer SOWs are frozen and are not regenerated.

B2  parseTableAmount fused digits across spaces (lib/sow/table-schema.ts)
    "Phase 1 5000" -> 15000, "Q1 2026" -> 12026. A milestone with a number in its label parsed as a different
    amount, passed the footing check and was written to payment_milestones at signing. Spaces/NBSP/apostrophes now
    group only as thousands (1-3 digit lead + exact 3-digit groups); any other second number = unreadable.

B3  An ASCII hyphen used as a separator read as a minus (same file)
    "Deposit - $500", "Fee - 1,500.00 USD", "Total - 12,500" parsed negative. A hyphen is now a sign only at the
    start of the cell or written directly against the number after whitespace/colon/currency ("$ -500",
    "USD -1,200.50", "Credit: -$500").

B4  "50%" in the Amount column parsed as 50 currency units (same file)
    Two 50% rows footed to a 100 contract and passed validation. Percentages are now unreadable, so the editor and
    send check ask for a plain number.

B5  "net 5,000" was ignored as a payment term (lib/sow/validate-send.ts)
    amountsStated skipped ANY number after "net". Now only plain 1-3 digit day counts ("net 30"), so a stated
    amount no longer triggers a false "does not state the contract value" warning or a redundant appended line.

B6  Single-section AI rewrite could change or drop figures (app/api/sow/regenerate-section/route.ts)
    Generation says "use ONLY the exact figures"; the rewrite only asked for clarity. Payment Terms / Revision
    Policy rewrites could alter amounts or round counts and were autosaved. Prompt now requires keeping every
    figure, and new lib/sow/figures.ts is a server backstop: if the rewrite's figure set differs from the original
    (unless the person typed a number into their instruction) the current content is kept (truncated + figuresChanged;
    SowEditor shows a specific message).

Known, intentionally unchanged: "Month 2 500" still reads as 2500 — a 1-3 digit number followed by an exact 3-digit
group is indistinguishable from "2 500" written with a space separator.

Tests: tests/sow-lifecycle-independent-pass-10.test.ts (15 cases).
