Workspace lifecycle — independent pass 3 (section 3)

Fixed
1. api/account/delete: owner_must_transfer (migration 080) had no entry in LEAVE_ERROR_MESSAGES, so a workspace
   creator deleting their account got the generic "could not leave this workspace". Now tells them to transfer
   ownership first (or delete the workspace).
2. api/workspace/create: workspace.created was the only audit_log write in the app bypassing logAudit(), so it was
   the one row without ip_address. Now goes through logAudit().
3. api/workspace/profile: an unchanged name still rewrote users.name and wrote a user.name_changed entry with
   previousName == new name. Now compares against the stored users.name and skips both (Auth metadata still syncs).
4. api/workspace/profile: the rename was audited only in the active workspace although the display name is
   account-wide. Now written to every workspace the person is an active member of (logSecurityAudit), with the
   active workspace as fallback. previousName is the stored name, not a session fallback.

Tests: tests/workspace-lifecycle-pass3.test.ts (4 of 5 fail on the pre-fix code; the 5th guards against
over-skipping when the stored name is empty). tsc clean; full suite 1531 passed, 75 skipped (pg-replay).
No migration.
