SECTION 13 — BUGS FIXED
 1. flags/[id] PATCH: un-hinted embed guardian_checks(...) is ambiguous (FKs in both directions) -> every flag
    action returned "Flag not found". Hinted !fk_flag_check. Same class: co/[id] outer guardian_flags embed
    -> guardian_flags!fk_co_flag.
 2. Duplicate detection never worked: pgvector comes back from PostgREST as text; cosine returned 0 for every
    pair. Now a pgvector RPC (guardian_find_duplicate_check) with an in-process fallback that parses the vector.
 3. stripHtml mangled PLAIN text ("load time < 2s and error rate > 1%" lost text; "<a@b.com>" vanished). New
    toPlainText() only strips content that actually contains HTML tags.
 4. Inbound quote-stripping leaked whole quoted threads (Outlook) / missed wrapped Gmail headers. Rewritten to cut
    at the first reply marker; forwards (the documented workflow) keep the forwarded body. Uses Postmark's
    StrippedTextReply when present.
 5. Classifier failed OPEN (missing/garbled creepConfidence -> "in scope", no flag, no failure record); contradictory
    verdicts silently resolved; matchedAgainst=amendment with no amendments. Now fail-closed / borderline.
 6. Unchecked writes: flag insert (check/inbound/retry), verdict write, exceptions_log insert. Shared pipeline
    (lib/ai/guardian-pipeline.ts) checks every write and returns a check to the retryable state on failure.
 7. No compare-and-swap: double-submitted exception created two exceptions_log rows; retry could double-flag;
    resolve/close/confirm/dismiss/escalate races. All CAS now (+ unique index one-exception-per-flag).
 8. Inbound lost mail: rate-limited -> 200 drop; failed insert -> 200; no MessageID idempotency. Now stored,
    queued for the sweep, 500 on failed insert (Postmark redelivers), idempotent on MessageID.
 9. Inbound accepted any non-archived project (Draft etc.) and used an unanchored address regex
    ("evilproj-x@...", "proj-x@guard....evil.com" matched). Anchored; no AI spend without a signed SOW.
10. scope-adjustment: trusted client oldValue, wrote snapshot before history (unaudited change on failure),
    no type/length/duplicate validation. Now server-derived old value, history-first with rollback, validation.
    append_scope_deliverables now bumps snapshot.version so the CAS sees CO appends.
11. Input validation: content type/length (20,000 cap), estimatedValue (Infinity/"12abc"), escalation note,
    close reason, comment body, history cursor, source enum.
12. Housekeeping: attachment extension sanitising + content-length precheck; comments now bump flag updated_at
    (stall reminders fired on active flags) and notify BOTH resolver and escalatee; randomUUID imported;
    scope-health-rollup: concurrency pool + time budget + rotating start (tail starvation) + deferred count;
    guardian-health: exact count queries over classifiable checks only (was a 1,000-row capped select
    diluted by unclassifiable rows) + per-workspace breakdown in alerts.
    (ai_usage_log pruning and the expired-CO flag release were fixed upstream by other sessions meanwhile.)
