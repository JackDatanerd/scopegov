Independent audit pass — Sections 13 (Guardian / scope governance) + 14 (Clients)
==================================================================================

Two files changed, two bugs fixed. No feature gaps found in either section this
round.

1) app/api/scope-governance/[entityType]/[entityId]/attachments/route.ts
   Bug: uploading evidence to a flag never touched guardian_flags.updated_at.
   The sibling comments/route.ts already bumps updated_at on new comments,
   specifically because cron/guardian-flag-stall measures inactivity by
   updated_at — without this, uploading fresh evidence didn't reset that
   clock, so the stall cron kept nagging about flags someone had just acted
   on. Attachments POST now bumps guardian_flags.updated_at the same way,
   only when entityType === 'flag'.

2) app/(app)/clients/[id]/page.tsx
   Bug: the Delete-client button (ClientDangerZone) was gated on
   canEditClientData (CREATE_PROJECTS) AND canDeleteClients (DELETE_PROJECTS).
   The backend DELETE /api/clients/[id] route only ever checks
   DELETE_PROJECTS — consistent with the sibling DELETE /api/projects/[id]
   route, which also gates purely on DELETE_PROJECTS. A role holding
   DELETE_PROJECTS but not CREATE_PROJECTS was fully authorized by the
   backend to delete a client, but had no button to do it with in the UI.
   canDelete now checks canDeleteClients alone, matching the backend.
   canMerge is untouched — the merge route genuinely requires all three
   permissions (CREATE_PROJECTS, VIEW_CLIENT_DATA, DELETE_PROJECTS), and the
   page's canMergeClients already matched that correctly.

Both fixes verified by re-reading the full call chain (route -> cron ->
page -> component) after editing, not just the diff.
