WHAT IT DOES (Pro and above)
- Settings -> Integrations -> Google Drive: connect, see the account and a link to the folder, choose which document types to archive
  (signed SOWs / accepted change orders), turn archiving off, "Archive past documents", disconnect / reconnect.
- Each executed document is saved as ITS ORIGINAL FROZEN PDF in the agency's own Drive:
      ScopeGov Archive / Acme Ltd / Website Redesign / SOW-Website-Redesign-v1-signed.pdf
                                                       CO-0003-Second-landing-page-accepted.pdf
- Design decisions made for you: COPY not link (the agency keeps a durable record that does not depend on ScopeGov; ScopeGov stays the
  source of truth); scope drive.file ONLY (the app can see only what it created, never the rest of the Drive); frozen PDFs ONLY (a
  contract with no stored PDF is skipped with the reason and never re-rendered — the codebase deliberately refuses to re-render an
  executed document because a fresh render can differ from what was signed); invoices NOT archived (rendered on demand, not stored).

HOW
- Reuses the 165/167 tables: a connection (the encrypted refresh token) and ONE rule per connection (kind 'google_drive'), so queueing,
  retries, backoff, plan gate, lapsed handling and the cron are shared. delivery.ts gains a Drive branch using the same settle().
- lib/integrations/drive-archive.ts: resolves the document (must be this workspace's and executed), stops if already archived, reads the
  frozen PDF, mints an access token, ensures root/client/project folders, finds-or-uploads (resumable) the PDF, records it.
- Idempotent: migration 170 adds integration_external_refs (unique per connection/type/key). A retry or duplicate event is a no-op; a
  file or folder created just before a crash is re-found by its Drive-side appProperties marker instead of duplicated.
- Self-healing: the leaf folder is verified each time (a trashed folder still accepts uploads — invisibly); if it is gone or trashed
  the folders are rebuilt once. A parent's trashing marks children trashed, so checking the leaf covers the chain.
- Connect creates the root folder immediately, so the commonest setup mistake (Drive API not enabled) shows on day one ("Drive could
  not be used"), not when the first contract is signed. The OAuth callback additionally requires the Drive scope to have been left ticked
  (Google lets people untick it) and a refresh token (without one archiving would stop within the hour).
- A shared lib/integrations/oauth-state.ts now serves Slack AND Google (purpose mixed into the signature: a Slack state cannot be used
  for Google). Slack delegates to it with the same signature domain, so in-flight Slack states still verify; all Slack tests pass.
- Outcome mapping: Drive full -> rule off + reason; revoked grant / 401 / refused -> connection flagged, rules off, "Reconnect";
  rate limit / 5xx / timeouts -> retry; folder gone -> rebuild; a document that cannot be archived (no frozen PDF, not executed,
  over 25 MB) -> dead for that delivery ONLY and it does NOT count toward the rule's 10-failures auto-disable (otherwise a backfill
  over old contracts would switch archiving off).
- Only Google hosts are ever contacted; the resumable-upload URL Google returns is checked against the allow-list before any bytes go.
