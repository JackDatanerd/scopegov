scopegov — Section 9 (SOW lifecycle) + Section 10 (CO logic) RE-PASS fixes
============================================================================
Independent, cold second audit pass (476adfb's own findings treated as if
they didn't exist), fixing what surfaced fresh. Applied against HEAD
91b2e96. Requires a Supabase migration (037) in addition to the code.

NEW FILES (2)
-------------
  lib/documents/co-version.ts
      Race-safe, lineage-scoped CO version allocator. Mirrors
      lib/documents/sow-version.ts's pattern (bounded retry against a
      unique-index collision) but scoped to a CO's own root_co_id
      lineage rather than the whole project — see migration 037's
      comment for why project-wide scoping is actively wrong for COs.

  supabase/migrations/037_co_lineage_version_uniqueness.sql
      Adds change_orders.root_co_id (NULL = "I am my own root"),
      backfills it for existing revisions, dedupes any pre-existing
      (lineage, version) collisions, and adds
      UNIQUE(COALESCE(root_co_id, id), version). RUN THIS MIGRATION
      before/with this code — app/api/co/[id]/revise/route.ts now
      selects root_co_id and will error without the column.

MODIFIED FILES (8)
-------------------

SOW lifecycle:

  app/api/portal/sow/[token]/sign/route.ts
      createMilestones()'s 'monthly' retainer branch created its
      payment_milestones row with due_date = NULL. app/api/cron/
      retainer-milestones de-dupes each month strictly by matching
      due_date to the 1st of the target month, so that NULL could never
      match — the cron's first run after signing inserted a SECOND
      full-amount "Monthly retainer" row for the same month. Now sets
      due_date to the 1st of the signing month, giving the cron the key
      it needs to recognize month one as already covered.

  app/portal/sow/[token]/page.tsx
      lib/pdf/renderer.tsx deliberately excludes 'parties' and
      'signature' from its generic section loop because both already
      have dedicated blocks (info box, signature lines). This page has
      the same info box and its own interactive sign action but never
      applied the matching exclusion — the 'parties' section's
      boilerplate text was printing a second time, restating the info
      box directly above it. Now excluded, matching the PDF.

  app/api/portal/sow/[token]/decline/route.ts
      withdraw() nulls sow_documents.token on the row as hygiene
      (revoked_tokens is what actually enforces the block, but a live
      JWT sitting on a dead row is needless exposure). decline() never
      matched that. Now does.

  app/api/sow/regenerate-section/route.ts
      sectionId was never validated against anything — a request for a
      table-only section id would still spend a model call for prose
      that's never rendered anywhere. Now rejected with 400 if sectionId
      isn't one of lib/ai/sow-content.ts's AI_SECTION_IDS.

  lib/pdf/rich-text.tsx
      'pre' was missing from the recognized block-tag set even though
      lib/utils/sanitize.ts's allowlist (which this file's own header
      comment claims to be exhaustive against) includes both 'pre' and
      'code', and Tiptap's unconfigured StarterKit reaches its CodeBlock
      extension via a markdown input rule with no toolbar button needed.
      A code block's raw <pre><code>...</code></pre> fell into the
      loose-text fallback and downgraded to plain inline monospace text
      merged into whichever paragraph it landed next to. 'pre' is now a
      recognized block, rendered as its own bordered monospace box.

CO logic:

  app/api/co/[id]/revise/route.ts
      Computed the next version as MAX(version) WHERE project_id = X —
      project-wide, unguarded, and the wrong scope. Two bugs in one:
      (1) a race — two concurrent revises could insert at the same
      version, same class migration 031 fixed for SOW; (2) scoping — a
      project can have several independent CO lineages living side by
      side (every new top-level CO starts at v1 via the column default,
      so multiple rows legitimately share project_id+version=1 today), so
      a project-wide max could jump a revision's version number to
      whatever an unrelated CO in the project happens to be at. Now uses
      insertNextCoVersion (new file, above), scoped to root_co_id.

  lib/documents/accept-co-counter.ts
      app/api/portal/co/[token]/accept/route.ts and countersign/route.ts
      both include document_id when marking a rotated token
      'superseded' — that's what lets a client who revisits their
      original email resolve back to the live CO instead of a dead
      "link no longer active" page. This was the one token rotation in
      the CO lifecycle that left document_id out: accepting a client's
      counter-offer retires their original "please respond" token
      (which stays live, un-rotated, all the way through the 'countered'
      stage) without it. Now included.

  app/api/co/[id]/remind/route.ts
      The 'stalled' -> 'awaiting_response' un-stall update ran BEFORE
      the actual Resend call. If the send then threw, the CO was already
      un-stalled with a fresh sent_at — looking actively followed-up-on
      even though the client got nothing — and the cooldown this same
      request had just logged blocked an immediate retry. Moved the
      un-stall to after a successful send; left the pre-send audit-log
      write alone (that one's a deliberate, documented race-narrowing
      trade-off, not the bug).
