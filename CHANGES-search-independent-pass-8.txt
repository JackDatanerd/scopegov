Search section (20) - independent pass 8
========================================

BUG: project-restricted members lose search results (and registry pages) once they are on many projects.
  /api/search read the member's whole project_members list (unpaged, so silently capped at 1,000 rows) and put
  every id into the `.in(...)` URL of every project-scoped query (projects, change orders, SOWs, invoices, flags,
  3-6 queries each). project_members rows are never removed when a project completes or archives, so the list only
  grows; at ~37 bytes an id the request URL passes gateway limits after a couple of hundred projects and all five
  blocks fail on every keystroke ("Some results couldn't be loaded"), leaving only clients / contacts / team.

FIX: the restriction is now an embedded filter through the relationship, in the database
  (lib/utils/member-project-scope.ts: project_members!inner(workspace_members!inner(user_id, status)) + two .eq
  filters on that path). Constant-size requests, no row cap, active memberships only (same rule as the
  project_members_active view, migration 070). Search keeps a head COUNT to short-circuit "member is on no projects".
